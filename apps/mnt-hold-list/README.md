# MNT Hold Lot List

Open from QA Page, choose the workbook, review the preview, and Save imported history. Continue using the same Report series when updating your workbook. Numbered sheet suffixes determine chronology (Sheet10 follows Sheet9). Full lot identifiers are trimmed and uppercased; sublots remain separate. Explicit lot dispositions override customer reply text. The top reply is read before quoted mail headers or signatures. Blank dispositions without a clear customer reply are Hold / pending customer disposition. Conflicting text and differing dispositions for the same lot in the latest sheet are Review. Comments across continuation rows and lot-matched FT summary rows are retained. Each source table row remains in history, including repeated lots with different FT operations.

Reimporting a source row updates its contents without duplicating it. Missing older rows are retained; deleting sheets does not erase saved history. New latest-sheet entries update the existing lot and may release or hold it again. A release-only lot creates a new entry; unavailable prior test details remain unavailable. The table supports search, status filters, expandable FT details and all history. Trend shows unique lots by disposition per sheet, not calendar dates. Quoted mail dates are not used as disposition dates.

History is stored in this browser under this site origin, independently of the existing Firebase tools. Backup JSON preserves complete history; Restore merges missing records without overwriting current records. Export filtered CSV opens in Excel. Back up regularly and before moving browser/computer or changing the site address. No new Firebase rules or deployment are required for this local history mode. Sheet numbers should be unique across the continuing report; separate series share the same numeric precedence.

Run the existing QA site as usual (GitHub Pages or local HTTP server). Excel reader uses the same SheetJS CDN as the other tools, so workbook import requires internet access. Existing tool logic and Firebase settings are preserved.

## v24 layout
Current lots are grouped by their latest numbered sheet under a Comment heading. Original top reply text is displayed for each sheet. Triggered BIN & V/F appears next to yield; HB5 uses B5 / InQty and is displayed as a percentage with its quantities. Multiple triggered bins show separate rates. Missing quantities display Unavailable; LY and non-bin triggers retain their original label. FT detail opens a popup with one separate one-row table per test result, keeping each lot and operation separate. FT summary yield takes priority over the verification table yield. The visible history and reason columns and disposition filenames are removed. Stored events remain available for continued disposition updates and backup. Reimport a workbook once to populate sheet Comment text in previously saved entries.

## v25 Firestore controls
Save to Firestore uploads all browser hold events to the existing MTK Firebase project, isolated collection mntHoldLotEvents. Load Firestore merges by event ID and import time. Existing local data is migrated only when Save to Firestore is pressed. Enable anonymous authentication (as for other QA tools) and publish the supplied firestore.rules in this project first. No cloud connection is attempted until a cloud button is used.

Delete saved MNT Hold data asks for confirmation and deletes the MNT Hold local storage key from this browser, clears the displayed lot summary and pending import, and closes the FT detail popup. It works without internet, Firebase authentication or Firestore rules. It does not delete optional Firestore copies or data for NPI or other tools. Back up before deletion. Cloud rules follow the existing project's signed-in access model. No live Firebase data was read, changed or deleted during development.

## v26 storage clarification
The default storage is browser local storage under mnt-hold-history-v1 for the current site address. The delete control always clears that browser data and cancels any pending workbook import. Firestore save/load remain optional, explicitly labeled controls. No cloud upload occurs when Save imported history is used.
v27: Release to next / Release to next process are recognized as Released. Existing pending entries with these saved sheet comments are corrected when the page loads. Explicit lot dispositions still take priority. Entries without saved comments require workbook reimport.

## v28 upload priority and separate files
Latest saved workbook upload takes precedence over older uploads, even when its sheet number is lower. Within one upload, the highest sheet number wins. Source records are keyed by report series + filename + sheet + row + lot, so files with the same sheet names remain separate. Comment sections also include the filename, while the Latest disposition column remains free of filenames. The same filename is treated as the same workbook source, and reimport refreshes its records and upload priority without duplicating those rows. Files with different names remain separate. Deleting the original Excel file does not delete stored events. The application's Delete button still clears all local MNT Hold data. Old stored records use their import timestamp as their initial priority.
