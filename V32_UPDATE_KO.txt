v32 적용 안내

기존 웹사이트의 앱 폴더를 이 패키지 내용으로 교체한 뒤 Ctrl+F5로 새로고침하세요.
shared/vendor 폴더도 함께 배포해야 합니다. AI/BI와 NPI의 Excel 읽기는 이 폴더의 로컬 라이브러리를 사용합니다.
이 패키지는 수정본이며 운영 사이트에 직접 배포하지 않았습니다.

1. Report 발송 관리
첨부 Excel의 Report Due date에 N/A를 입력한 뒤 다시 업로드하면 발송 목록과 지연 집계에서 제외합니다.
다운로드 Excel에는 원본 N/A를 유지합니다. 다시 날짜를 넣고 업로드하면 해당 건을 다시 계산합니다.

2. AI/BI 비교
1차 공정 분류 → 2차 공정별 변경점 순서로 표시합니다.
공정명 사전 목록 없이 코드 [약어] = 공정명 형태를 인식하며 AI/BI 접두사, 전각 문자, 분리된 제목 셀을 지원합니다.
예: 520 [PCM] = PACKAGE CHIP MOUNT / AI 003 [B/G] = BACK GRINDING / BI BD010 [DEW] = Descum-WF.
다른 양식은 공정 제목 형식 설정에서 {code}, {abbr}, {name}을 사용해 입력하세요.
예: 공정 {code}: {name}. {name}과 {code} 또는 {abbr}가 필요합니다.
형식은 브라우저에 저장됩니다. 비우면 자동 인식으로 돌아갑니다.
코드·약어 조합, 코드, 약어, 공정명이 각각 유일한 경우 순서대로 연결합니다.
반복되어 연결이 불명확하면 연결 확인으로 표시합니다. 공정 제목이 인식되지 않으면 경고와 미분류 결과를 표시합니다.
공정 추가·삭제·이동을 구분하고, 연결된 공정 안에서 행·셀 변경을 비교합니다.
동일 공정은 1차 목록에, 차이가 있는 공정은 2차 변경점에 표시됩니다. 공정/변경 구분 필터를 사용할 수 있습니다.
시트명 19→20처럼 변경되어도 문서 번호에서 개정 번호를 제외한 값이 유일하게 일치하면 연결합니다.
파일명을 숫자로 사용해도 됩니다. 여러 후보가 있어 연결할 수 없는 시트는 전체 추가/삭제로 유지하므로 원본을 확인하세요.
값·수식 비교이며 이미지, 도형, 서식, 메모는 비교하지 않습니다.

3. NPI
파일 내부 고객/Customer/Customer Code 정보를 우선 사용합니다. 없으면 파일명에서 고객을 추정합니다.
Austin NPI는 파일 내 고객 칸이 BDR이므로 BDR로 인식합니다.
신규 고객은 입력란에서 확인·수정할 수 있고 저장하면 필터·지표·백업 복원에도 표시됩니다.
같은 파일명·같은 시트를 새 고객으로 재저장하면 기존 분류를 교체해 중복을 방지합니다.
여러 고객 코드가 섞인 파일은 임의로 한 고객에게 합치지 않고 고객별 파일을 안내합니다.

검증
A/B 실제 파일: 12개 공정, 기본 정보 11건 및 PCM 6건의 변경을 검출했습니다.
Austin NPI 실제 파일: BDR, 9개 시트, 19개 원본 Lot 행을 가져왔습니다.
N/A 입력/다운로드/재업로드, 신규 고객 복원, 다양한 제목 형식·공정 이름/코드 변경·추가·순서 이동·반복 공정 테스트를 통과했습니다.
파일 처리 및 화면 HTML 생성 함수로 검증했습니다. 이 PC의 자동 브라우저 실행 오류로 화면 실기동 검증은 완료하지 못했습니다.
